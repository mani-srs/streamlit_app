## Context
- **Where LLM calls are logged today:** `core/llm.complete()` logs each Cortex call through `ctx.obs.llm_call()`, recording run, stage, role, model, tokens in/out, latency, retries and status. That log is **in memory** (`MemoryObs`) unless the optional Snowflake app tables exist, so the Observability numbers are lost when the app restarts. Run state already survives restarts in `.state/runs.sqlite`, through the run registry plus LangGraph checkpoints.
- **Snowflake's billing record:** `SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY` is readable with your role. It has one row per `QUERY_ID`, with `CREDITS`, `MODEL_NAME`, a token breakdown in `METRICS` and a `QUERY_TAG`, bucketed hourly and arriving with a delay of hours. It already shows 40 `AI_COMPLETE` calls, 0.752 credits, over the last 3 days.
- **Rates from your own bills:** billed rows fit `claude-4-sonnet` at **1.8 credits per 1M input tokens and 9.0 per 1M output tokens**, exactly.
- **What's missing:** the app doesn't record each call's Snowflake query id, so its calls can't be matched to billed rows yet.

## Design decisions (assumptions — adjustable later in the UI or config)
1. **Two cost figures side by side:**
   - **Estimated credits:** available instantly, tokens × per-model rate from `config/pricing.yaml`. It's seeded with the claude-4-sonnet rate above and can be recalibrated from billing data.
   - **Billed credits:** the exact figure, matched later from ACCOUNT_USAGE by query id.
2. **Dollars are optional.** You enter a price per credit once in the Financial page settings, saved to `.state/settings.json`. Until then everything shows in AI credits, which is how Snowflake bills Cortex.
3. **In scope:** Cortex COMPLETE credits made by this app.
   - **Not included:** the warehouse time those queries use, Cortex Code/CoCo usage while building the app, and Databricks costs. The page says so.

## Implementation steps
1. **Record the query id of every Cortex call.**
   - `core/db.py`: add `query_with_id()` returning rows plus the Snowflake query id (`cursor.sfqid`). It's safe across threads because each call gets its own cursor.
   - At connect, set a fixed session tag `QUERY_TAG='sf2dbx_migration_app'`, so the app's calls can be told apart from other Cortex use in the billing view.
   - `core/llm.py`: `_cortex_backend` uses it, and `query_id` is added to each logged call.
2. **Keep the call and step logs across restarts.**
   - New `SqliteObs` in `core/persistence.py`, stored in the same `.state/runs.sqlite`: an `llm_calls` table (including `query_id`, `billed_credits`, `billed_at`) and a `nodes` table.
   - `Backend` uses it whenever a state file is set; writes also go to the Snowflake app tables when configured.
   - Add a `query_id` column to `OBS_LLM_CALLS` in `setup.sql`.
   - `Runner.list_runs` gets a larger limit for History.
3. **Shared analytics module, `core/analytics.py`** (pure functions, unit-tested):
   - `run_summary(state, calls)` → per-run row: created/updated, duration, slice, object count and types, status, current step, MAPPED/HYBRID/AI counts, AI slots filled, check errors/warnings (top rules), revisions per gate, files, calls, tokens, estimated/billed credits.
   - `estimate_credits(model, tokens_in, tokens_out, rates)`.
   - `calibrate(rows)`: least-squares fit of the input/output rate per model from matched billed calls.
   - `reconcile(db, calls)`: fetch billed credits for unmatched query ids from `CORTEX_AI_FUNCTIONS_USAGE_HISTORY` within the last 30 days; missing access is handled gracefully.
4. **New `config/pricing.yaml`:** `claude-4-sonnet` at 1.8 / 9.0, marked as derived from your bills on 2026-09-28. `llama3.1-70b` is left empty until calibrated, with a warning. The loader handles a missing file or missing PyYAML.
5. **History page, `app_pages/history.py`:**
   - Filters: date range, status, slice search.
   - Summary metrics: runs, success rate, objects converted, % converted by rules vs AI, total AI slots, check errors, total tokens and credits.
   - Charts: runs per day by status, objects by type, rules/hybrid/AI split, most frequent check findings.
   - Run table: sortable and exportable as CSV. Selecting a row gives buttons to open that run in Run monitor, Review gate or Outputs.
6. **Financial page, `app_pages/financial.py`:**
   - Settings: price per credit and an optional monthly credit budget with a progress bar.
   - Metrics: calls, tokens in/out, estimated credits, billed credits and how many calls are matched, dollars if a price is set, average cost per run / per object / per AI slot.
   - Breakdowns: by model, role, step, run (top 10), and a daily trend.
   - **Billing tab:** "Refresh billed credits", "Calibrate rates from billing", and an account view of this app's billed Cortex usage over the last 30 days, which also covers the 40 calls made before query ids were recorded.
   - Cost notes explaining what's included.
7. **Navigation:** add "History" and "Financial" to `streamlit_app.py`. Keep Observability for latency and step timings.
8. **Tests and docs.**
   - Unit tests: `SqliteObs` survives a new backend; the query id is recorded (fake database); cost estimate and calibration maths (it must recover 1.8/9.0 from the real rows above); run-summary aggregation.
   - Headless UI tests: both pages render with seeded data and with no data.
   - Docs: USER_GUIDE (new pages), ARCHITECTURE (cost model, billing matching), app_pages / core / config READMEs, root README key facts.
